# Python modules

`run_offline_review.py` runs the eleven cached review steps in dependency order using QGIS Python. Close QGIS first because open rasters can prevent overwrites on Windows. It requires completed seasonal/terrain/rainfall inputs and May context tables; it does not download data, authenticate, rebuild source composites or perform rainfall extraction. It stops on the first failure, logs each step and writes an incomplete/complete run manifest plus final product hashes under ignored `data/processed/integrated_evidence_review/`. All eleven steps passed in a complete run with QGIS closed; product hashes, 49 reopened layers and the three-page report were checked. This is cached-review verification, not independent scientific validation.

`review_optical_confounding.py` runs offline with QGIS Python to quantify NDMI/NDVI change-sign overlap and descriptive rank correlation under three water-mask scenarios. A separate arbitrary ±0.02 sensitivity band checks near-zero changes. It checks category totals against common valid support and writes CSV/notes under ignored `data/processed/multiyear_2023_2025/surface_patterns/`. Shared NIR bands and spatial dependence preclude interpreting agreement as independent validation or irrigation identification.

`explore_terrain_mcda.py` runs offline with QGIS Python after scenario/confounding reviews. It tests three hypothetical terrain-only inverse-slope/TWI weight scenarios plus two single-indicator omission checks, each under percentile-rank and 2nd/98th-percentile clipped-linear normalization. Ten scenarios use identical masked support, with 45 ranking/upper-fifth comparisons. Outputs under ignored `data/processed/terrain_scenarios/` are exploratory terrain-setting scores, not groundwater-potential maps. No final combined weights are selected. See `docs/06_scenario_review.md` for assumptions and findings.

`build_integrated_evidence_review.py` runs with QGIS Python after the local review outputs exist. It assembles 49 styled map/table layers, including ten terrain-only scenarios and the automated optical-confounding table, into ignored `data/processed/integrated_evidence_review/venkatapur_evidence_review.qgz`, with relative paths, EPSG:32644, an inventory and opening instructions. It reloads the saved project and checks that all layers are valid. Sibling processed folders remain required; it is not a standalone share bundle. No downloads, credentials or final combined score.

`build_analysis_review_report.py` runs with QGIS Python after the rainfall, temporal, terrain and sensitivity summaries and terrain figure exist. It creates `venkatapur_analysis_review.pdf` in the integrated review folder, drawing findings from local CSV results and documenting scope and remaining gaps. It validates complete May rainfall before reporting totals. No new data or final model is produced.

`review_drainage_thresholds.py` runs offline with QGIS Python after drainage diagnostics. It compares density under 0.25, 0.5 and 1.0 km² contributing-area thresholds on identical valid support, recording descriptive rank correlation and local upper-third overlap. Outputs are under ignored `data/processed/terrain_pilot/drainage_diagnostics/`. It does not assign groundwater-suitability direction or recompute distance-to-drainage.

Offline review scripts: `review_rainfall_context.py` uses the Earthdata environment to validate May daily totals and summarize prior complete UTC days before selected acquisitions. With QGIS Python, `review_may_optical_rainfall.py` and `review_may_radar_rainfall.py` compare individual images on common pixels; `map_surface_change_patterns.py` creates descriptive multi-year sign-pattern maps and a QGIS review project; `review_terrain_surface_patterns.py` summarizes terrain thirds, seasonal moisture levels and vegetation changes; `plot_terrain_surface_review.py` creates a PNG/PDF figure from that summary. Outputs remain under ignored `data/processed/`. Run terrain summaries before the plot. See `docs/06_scenario_review.md` for interpretation, sensitivity assumptions and unresolved confounding. These scripts do not assign MCDA weights or validated groundwater classes.

`extract_imerg_month.py --year 2025 --month 5 --max-new-days 3` runs in the Earthdata `.venv`, logs in privately once per run and resumes daily/interval checkpoints. The default batch limit is three new days; the trial suggests roughly 65 MB transfer per batch, with actual size variable. `--summary-only` validates cached days and generates a coverage report without login/network access. Existing completed days are validated and reused. CSV/monthly outputs are under ignored `data/processed/rainfall_context/`; original native-cell rates remain under ignored `data/interim/public_inputs/rainfall/imerg_uncal/`. Monthly totals require every half-hour interval to be valid; otherwise totals stay blank and available observed sums are separately labelled. Do not interpret partial sums as complete totals. Each authenticated run keeps credentials only in memory; reruns require login again. Synthetic integration/duplicate tests and cached-day/interval recovery checks have passed; live multi-day processing still requires the user's local authentication.

`extract_imerg_day.py --date 2025-05-12` uses the separate Earthdata `.venv` to test actual uncalibrated rainfall extraction for one complete UTC day. The user authenticates interactively once per run; no credentials persist. It reads only bounded remote HDF5 ranges (8 MB ceiling per file), requires `Grid/Intermediate/precipitationUncal` and recognized mm/hour units, and writes intersecting native-cell rates plus complete-day totals under ignored `data/interim/public_inputs/rainfall/imerg_uncal/`. It checks 48 unique half-hour starts and does not fill missing observations or substitute gauge-adjusted precipitation. The two native cells are regional context, not an area-weighted village average. This first-day extraction does not provide seasonal or annual rainfall; validate it before extending the time range. Synthetic reader tests do not substitute for the user's authenticated live-file check.

`check_earthdata_access.py` runs in the separate Git-ignored `.venv`, using `requirements-earthdata.txt`. `--catalogue-only` searches one public IMERG V07 half-hourly granule without credentials. Running without that flag prompts privately in the user's terminal via `earthaccess.login(strategy='interactive', persist=False)` and tests an eight-byte HDF5 header read. It does not save a password, token, cookies or a full rainfall file; only a sanitized result under ignored `data/interim/rainfall_access_check/`. Browser sign-in does not authorize the script. Interactive authentication must be performed by the user locally, not by sending secrets through chat. Because login is not persisted, later extraction requires another login. The actual uncalibrated variable and units still need inspection before rainfall aggregation.

`review_multiyear_sensitivity.py` compares the 2023-2025 summaries under named water and vegetation exclusions. A water year is flagged when either seasonal frequency is >=0.5; recurrence requires >=2 of 3 known years. The vegetation assumption uses NDVI >0.3 in either season, recurring in >=2 years. It does not identify irrigation or crops. All optical flags use a full-support 30 m alignment check. Outputs under ignored `data/processed/multiyear_2023_2025/sensitivity/` include scenario masks/maps, statistics, descriptive correlations and a QGIS review project. Large changes in retained area mean scenarios cover different populations; do not interpret differences as causal effects or select combined weights automatically.

The seasonal optical/radar scripts also accept `--year 2023` and `--year 2024` (default remains 2025). Each year uses separate cached source and output folders. After running both sensors for 2023, 2024 and 2025, run `summarize_multiyear.py` with QGIS Python. It writes 30 m multi-year seasonal medians, within-year seasonal-change medians, paired-year counts, change IQR and sign consistency to ignored `data/processed/multiyear_2023_2025/`. Every summarized pixel requires three valid paired years for change outputs. Optical annual indices are area-averaged with a full-support check before temporal aggregation. This three-year subset does not replace the entire planned 2021-2025 baseline. Water/crop confounding, rainfall and field assessment remain pending; temporal consistency is not prediction confidence.

`package_pilot.py` builds an offline review ZIP under ignored `data/processed/share/`, including a relative-path QGIS project, its required rasters/vectors, reference GeoJSONs, sanitized metadata, code snapshot, PDF overview, comparison figure and checksums. Run with QGIS Python after `create_pilot_review.py`. It uses the ReportLab and Matplotlib packages available in the installed QGIS environment. The release folder is protected against overwrite; rename an existing release before rebuilding. Extract the entire ZIP before opening `OPEN_IN_QGIS.qgz`. Packaging does not publish or upload anything and does not imply scientific validation. Reports explicitly mark rainfall, multi-year work and final weights as pending.

`build_s1_seasons_2025.py` queries Microsoft Planetary Computer Sentinel-1 RTC for matched Sentinel-1A IW VV/VH, relative orbit 165 descending, slice 15. It downloads small gamma0 intensity windows to ignored `data/raw/sentinel/s1/seasons_2025/` and creates 30 m seasonal linear medians, dB medians, valid counts and differences under ignored `data/processed/s1_seasons_2025/`. Run with QGIS Python. Anonymous temporary SAS access tokens remain in memory; they are never written to manifests. Existing windows are reused. At least three positive valid observations are required per pixel. Linear powers are aggregated before dB conversion. This replaces the raw-GRD/SNAP route for this pilot with provider-processed Catalyst RTC; do not mix with sigma0 or claim identical processing. Provider terrain source, orbit metadata and unresolved shadow/layover, speckle, geometry and crop/water confounding limitations are recorded. One year does not satisfy multi-year requirements; radar-response suitability remains unresolved.

`review_indicator_correlations.py` aligns computed seasonal optical medians to the terrain 30 m grid using area averages, requiring essentially full valid fine-grid support per target pixel. It writes pairwise Pearson/Spearman correlations and named water/vegetation exclusion scenarios to ignored `data/processed/indicator_review/`. Run with QGIS Python after seasonal, terrain and drainage processing. Water-frequency >=0.5 and NDVI >0.3 are sensitivity assumptions, not confirmed persistent-water, crop or irrigation labels. Pixel correlations are descriptive and spatially autocorrelated; no significance, predictive accuracy or validation claims are made. Combined weights remain unset.

`build_drainage_diagnostics.py` runs locally after the terrain pilot to create directed D8 stream segments and approximate drainage density within a 1 km radius, at 0.25/0.5/1 km2 contributing-area thresholds. Run with QGIS Python. It uses SciPy (included in this QGIS installation). Outputs are in ignored `data/processed/terrain_pilot/drainage_diagnostics/`. Density uses half of each segment's length at each endpoint cell and a discrete circular neighbourhood; it is not an exact vector intersection calculation. Neighbourhoods containing uncertain upstream flow are excluded. Stream vectors are clipped to the planning circle; neighbourhood density uses the larger processing extent. Existing vector output is protected against overwrite: review or rename it before rerunning. These remain provisional drainage diagnostics with no assumed suitability direction.

## Available processing scripts

- `download_s2_trial.py`: downloads the original two-date small-area trial.
- `process_s2_trial.py`: scales and masks those inputs and creates trial indices.
- `audit_s2_water_masks.py`: compares alternative water exclusions.
- `build_s2_seasons_2025.py`: downloads up to two distinct low-cloud dates per month for March-May and October-December 2025, then builds sampled seasonal medians, observation counts, separate water-frequency layers and a QGIS review project.
- `build_terrain_pilot.py`: creates a separate 30 m Copernicus GLO-30 DSM terrain pilot using GDAL and installed GRASS 8.4 D8 routing. Run with the same QGIS Python environment. It tries 30 km and 50 km processing extents and retains edge-underestimate flags. Outputs and the review project are under `data/processed/terrain_pilot/`; source subsets and GRASS working files remain under ignored `data/interim/` paths.

The terrain pilot uses Copernicus GLO-30 Public (AWS 2021 release), an explicit public-access alternative to the SRTM source proposed in the data plan. This is a surface model including buildings and vegetation. GRASS handles depressions with least-cost routing; no blanket depression filling or surveyed tank/depression mask is applied. Stream thresholds are 0.25, 0.5 and 1 square kilometre. TWI uses specific contributing area and a 0.1-degree slope floor. Pixels flagged as likely flow underestimates are excluded from hydrology outputs. Streams, depressions, open-water areas and boundary effects still require review. Stream vectors and drainage density remain pending. The manifest records the assumptions and affected-pixel counts. Seasonal optical layers retain their separate 20 m grid in the review project; no combined score is generated.

Run these with the QGIS Python environment, which supplies GDAL, NumPy and QGIS libraries. For the installed Windows version:

```powershell
& 'C:\Program Files\QGIS 3.40.11\bin\python-qgis-ltr.bat' src/build_s2_seasons_2025.py
```

The seasonal script uses anonymous public Earth Search COG access and downloads only study-area windows. Source data/metadata are under the ignored `data/raw/sentinel/s2/seasons_2025/`; outputs are under the ignored `data/processed/s2_seasons_2025/`. Existing downloaded windows are reused; derived seasonal outputs are regenerated on rerun. Keep input metadata paired with each window.

The 2025 seasonal pilot retains the trial's 20 m grid spacing, with a 100 m apron for shadow masking; it is not the planned final 30 m MCDA grid. Medians require at least three valid observations per pixel per index. Counts include zero inside the circle; outside is NoData. Reflectance offsets come from source metadata. Pixels with negative index-input reflectance or a near-zero denominator are excluded rather than clipped. SCL and MNDWI water frequencies are separate uncertain diagnostics; no automatic persistent-water exclusion is applied to the seasonal medians. Differences include surface water and must be interpreted accordingly.

The date selection is a small, month-balanced sample ranked by whole-tile cloud cover, not a complete seasonal archive or a guarantee of cloud-free AOI pixels. The manifest records dates, hashes, scales, thresholds and coverage. One sampled year does not meet the multi-year requirement in the data plan and must not be described as a validated groundwater-potential result.

The current workflow is satellite-only screening using transparent MCDA, following [the public satellite data plan](../docs/04_public_satellite_data_plan.md). No verified borewell labels are available. Do not train supervised models or generate success-probability rasters.

Planned processing stages cover input inventory, Sentinel preprocessing, terrain/drainage, rainfall summaries, grid alignment, separate named evidence scenarios and sensitivity comparison. Combined weights remain unset until the small-AOI inventory, correlation review and irrigation/crop-confounding review are complete.

Borewell-survey validation and supervised-ML material from earlier planning are optional future work, not the current workflow or a prerequisite for it. Verified survey observations may later support independent assessment. Any supervised-ML study would require a separately reviewed scope, suitable verified labels and spatial validation; no training scripts are planned for the current phase.
